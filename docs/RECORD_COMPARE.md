# P0 專項：邊播邊錄、既有影片比較、對齊與 VS 影片

狀態：設計與驗證計畫，不是已通過的相容性聲明。產品要求來自使用者提供的 Threads 貼文與 SyncMirror Player 參考頁；不仿製其程式、品牌或介面素材。

## 1. P0 完成定義

同一裝置上，使用者可選擇「播放示範並同時錄下自己」，或「選老師課後影片與自己已錄好的影片」。兩條入口都能校正兩側時間與鏡像，最後取得一個**左右畫面合成、帶示範音訊、能離開本網站再播放的影片檔**。只有兩支影片同時播放、截圖、外連剪片工具或要求手動拼接，都不算完成。既有影片入口於 2026-10-28 補入 P0 規劃，不依賴相機權限，也不取代原有錄影驗收。

初期驗收範圍：Salsa shine；單次 15／30／60 秒；示範錄影速度 0.5×、0.75×、1×；前景操作；建議輸出 1280×720、目標 30fps、全身等比 fit。解析度／fps 是請求及品質目標，不是所有手機硬體保證。不得因 Web 困難把這項偷偷降為 P1。

## 2. 最小完整使用流程

1. 選本機示範片段 A–B，指定練習速度。慢速後的實際時長不得超過本期 take 長度；可縮短片段。
2. 點「錄下我」，才要求相機權限。前鏡頭預設；先顯示取景、全身框線及獨立鏡像設定。麥克風預設關閉。
3. 點開始，3／5／10 秒倒數；相機先 ready，示範 seek 到 A 且音訊系統完成啟動後才倒數。拒絕權限／相機被占用時可重試。
4. 錄製開始後記下可觀測的單調時間與示範顯示時間，示範播到 B 或使用者停止。先後次序需用實測校正，不能把 JavaScript 同時呼叫當成同一影格啟動。
5. 完成自拍原片儲存與播放驗證，進比較頁。重錄要先保留／捨棄上一個 take，不靜默覆蓋。
6. 共同時間線播放、手動 offset、兩側鏡像。確認全身、方向、時間後再合成。
7. 匯出期間保持前景，進度可取消；完成後下載／系統分享保存，並重新開啟驗證。保存功能失敗要保留原片與配方供重試。

錄影不跨 A–B 重複回捲；每段是一個 take。練習循環可一直開，但「錄影模式」先固定區間、速度與方向，降低時間映射複雜度。八拍倒數、連續多 take 與錄音混音列 P1，沒有把手動改速度的變動時間線藏進 P0。

### 2.1 既有影片入口（#10／#11）

入口文案「比較已有影片」；左選老師課後原片，右選自己的練習原片。這是一般使用流程，不只藏在自拍測片／重連功能中。兩側載入均需實播驗證，取消、壞檔或不支援格式不改動先前可用配對；新片成功並由使用者確認後才換入。不請求相機或麥克風，不生成假的錄影中工作。

先各自定位同一動作：老師起點 A、終點 B，自己的起點 C；再使用共同時間線及手動偏移。採第 4 節同一映射，以 δ=C 建立初始配方，C 只作輸入，不另存一份可能與 offset 衝突的時間。預設 r=1；只有使用者確認自己當時跟著慢速示範跳，才手動選既有 0.5／0.75／1 的固定 r。r 是兩片的時間比例，不是讓兩片一起放慢的檢視速度；不依檔案時長或音訊猜比例。兩片節奏不等速、快慢變化或需要其他比例時，明示本期限制，不宣稱固定偏移能自動對拍。

例：老師 A=12、B=32 秒、自己的 C=4 秒、r=1，則比較第 0 秒對應老師第 12 秒／自己第 4 秒，兩片足長時輸出 20 秒。設定比較區間不修改原片；原片可長於 60 秒，本期先選最多 60 秒的比較／輸出片段，沿用既有長度護欄。合法交集為空時禁止播放比較／合成，尾端不足先顯示縮短結果；正負微調與越界均依第 4 節。

比較與輸出共用同一配方、鏡像、全身 fit 與音訊來源，左老師／右自己。自己原片的音軌預設不播放、不混入，老師無音軌時清楚顯示將輸出無聲。完成後保存可編輯配方，兩片原檔不刪除；外部選取的原片預設 session-only，保存副本由使用者明確選擇。重開缺任一片時保留配方並逐側人工確認重連，見 [DATA_FORMAT.md](DATA_FORMAT.md)。

桌面入口已實作，合成雙片與備份重連實測見[既有影片證據](evidence/existing-comparison.md)。G2–G4、G7 的桌面數據與十次「選片 → 校正 → 匯出」穩定性分別記錄，不延伸宣稱 G5 iPhone 保存或原本 G6 相機擷取通過；數值仍以第 5 節為準。G1 相機擷取在此路徑記為不適用，原本錄影路徑仍須獨立通過完整 G1–G7。

## 3. Web 實作候選

### 3.1 擷取自拍

`getUserMedia` 取得相機，預覽使用 `playsinline` 並靜音。用 MediaRecorder 保存自拍視訊；預設不錄環境聲，避免喇叭聲再次被收進輸出形成回音。來源音訊在示範影片內，匯出時從示範取得。

只使用 HTTPS／受信任 localhost。相機需要使用者授權；音訊啟動及播放可能需要手勢，流程不能靠自動播放假設。[相機 API](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。

錄影 chunks 依序落盤，計算時長不能使用「chunk 數 × timeslice」；事件間隔不保證準時。錄影中切背景、鎖屏、來電、攝影機被接管、旋轉導致尺寸變更，都要標記中斷並停止／完成可用資料，不在背景偷偷繼續。[dataavailable](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event)。

### 3.2 比較與合成

保留自拍原片，採「錄完後合成」：兩個 video 元素依共同時間線播放到 canvas 的左右矩形，使用 contain 避免裁掉腳；鏡像分別套用於各圖層。另可選半透明疊影輸出，自己的圖層先畫、老師依可見度覆蓋，沿用目前兩側大小／位置；這種版面會保留使用者縮放造成的裁切。兩種版面共用時間、音訊與原驗收門檻，分別成檔。Canvas captureStream 提供輸出視訊軌，MediaRecorder 編碼；不把支援較不一致的 video.captureStream 當必要路徑。[Canvas captureStream](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/captureStream)。

比較預覽及 VS 採隨速度自然變調；不套用瀏覽器音高保持，以避免受測慢速成檔的聲畫差。一般練習播放仍依能力保持音高，媒體操作結束後恢復同一練習設定。這不改時間映射、音訊來源或驗收門檻。

預設用來源影片音訊，透過 Web Audio 的 MediaElementSource → MediaStreamDestination 加入輸出 stream；源音訊到喇叭與輸出路徑分開控制，自拍音軌不混入。AudioContext 必須處理手勢恢復、暫停、音訊路由變動，測試慢速時音高及時間是否跟畫面一致。[來源節點](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/createMediaElementSource)、[輸出節點](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/createMediaStreamDestination)。

先偵測並試錄 MIME／codec 組合，再選裝置真正可工作的格式。`isTypeSupported()` 回 true 仍可能因資源失敗，最後要讀回輸出檔驗證。優先測 MP4/H.264/AAC；無此組合時測 WebM 路徑，副檔名必須反映真實容器，且另測在接收者裝置的播放。不能靠改檔名、付費雲端轉碼或強迫所有人安裝同一播放器過關。[編碼偵測](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)。

來源只接受使用者提供的本機檔案，避免跨來源 canvas 汙染與網站下載授權問題。輸出前預估原片＋自拍＋合成＋暫存的磁碟空間，chunks 落盤／完成 Blob 的記憶體峰值也要實測。不要把 60 秒所有中間結果重複讀進 ArrayBuffer。

第一候選是前景即時合成，匯出約需跑過一次片段；這是簡化工程的明示取捨，不承諾瞬間完成。WebCodecs／原生編碼可作後續比較，但未實測前不承諾高解析、背景匯出或無限片長。

### 3.3 Safari 本機音訊相容候選（2026-10-29，#3／#11）

Safari 合成改從同一老師原片的合法交集解碼 AAC，再以相同 r 自然變調；普通練習與共同預覽仍使用原片與原映射。來源為一般 MP4 的單一 AAC-LC、最多雙聲道／48kHz；一般 MP4 無音軌時輸出無聲。超出格式、8 MiB 音訊索引容器或 250,000 包索引預算時明示拒絕，保留原片、設定與前次 VS，使用者仍可改用 Chrome。Chrome 原有聲路與格式不變。

只準備至多 60 秒來源 PCM，不把長片整支載入音訊記憶體。取消、背景與失敗關閉解碼及本輪音訊節點；重試從目前老師片重新準備。詳細配置上限與不支援格式見 [來源庫 TECHNICAL 第 33 節，需連網](https://github.com/sunpochin/dance-stamp/blob/c0ab39bcf68354cc29d7048a0d81e56d626efcf1/TECHNICAL.md)；原 G1–G7、首尾覆蓋、來源音訊與下載驗證規則都不變。這是待獨立審查的候選，未代表 Safari／手機全數通過。

早期 eb8f10d 的正式桌面 Safari 證據有 1×／0.75× 的 15 秒通過，但 1×／30 秒被原同步護欄拒絕，0.5×／15 秒被原 v5 覆蓋／漂移檢查拒絕；不是整體 Safari 可用聲明。完整矩陣與十輪 60 秒仍保留，見[版本綁定證據](evidence/issue-3-bounded-audio.md)。

審查續修另外保護空 edit 的真正靜音，以及有音訊匯出時 AudioContext 與老師時間線的 G2 偏移；超標拒絕並保留前次 VS，不以修改 offset 或門檻掩蓋。以上原生結果仍屬其原受測版本，新修正版尚未完成 Safari 品質矩陣。

後續 Safari VS 候選限定使用原生 WebM／VP8／Opus，輸入端有界 AAC 範圍不變。這是比較匯出的專用選項，相機及 Chrome 仍依原格式順序；若明確格式不支援或無法啟動，清楚拒絕並保留原片、配方及前次 VS，不默退已知失敗的 MP4。下載使用真實 .webm，接收端／產品外播放另驗。私有原生單次1×／30秒通過原 v5，不能承接成正式新版本完整矩陣；來源與未驗證界線見同一證據及 [來源庫 TECHNICAL 第 36 節，需連網](https://github.com/sunpochin/dance-stamp/blob/c0ab39bcf68354cc29d7048a0d81e56d626efcf1/TECHNICAL.md)。 正式41b3023／f81d1c69861fa21e另完成自己的原生Safari半速15秒單輪，原v5的聲畫／覆蓋／漂移檢查通過；仍不代表完整矩陣、十輪穩定性或本檔網站外播放通過。


## 4. 時間與鏡像契約

所有持久化時間用整數毫秒；下列公式用秒說明。令：

- A、B：示範來源片段起訖。
- r：錄影時固定的示範播放速度，0.5／0.75／1；既有影片比較預設 1，僅依使用者確認的跟跳速度手動設定。
- t：練習經過時間，以示範開始為基準。
- δ：自己的影片 offset，正值代表原片需要略過開頭 δ 秒才能對齊；既有影片入口以自行選定的起點 C 初始化。
- D：自拍原片的實際長度。

映射：**示範時間 = A + r × t；自拍時間 = t + δ。** 合法交集是 `L=max(0,-δ)` 到 `U=min((B-A)/r,D-δ)`；若 U≤L，禁止合成。輸出 u=0 對應 t=L。來源音訊也從 A+rL 開始，不能只移畫面不移聲音。

例：示範 A=10、B=25 秒、r=0.5，實際跟跳 30 秒；自拍 δ=0.2 時，略過自拍前 0.2 秒。輸出保持這次練習速度；第一版不自動把慢速 take 加速回原曲。若自拍尾端不足，只合成交集並先顯示長度縮短，不能偷偷補黑格。

共同 scrub 後等待兩側 seeked 再播放；以前景主時鐘控制，觀察偏差才修正，不在每個畫面硬 seek。起始延遲可手動校正，60 秒內逐步累積的漂移不能只靠固定 offset 假裝修好，須修排程或改平台。

分開保存 `referenceMirror`、`selfMirror`、`previewMirror` 與取景方向；預覽像鏡子不代表原始自拍檔已翻轉。合成必須讀同一份配方，不再次隱含翻轉。用左右有 L/R 標記的合成測片核對畫面與控制文字。

決策：

1. **iPhone Web 與桌面核心 gates 通過**：採 Web P0，公布實測範圍。Android 問題排在 iOS 後處理。
2. **桌面通過、iPhone Web 有可重現阻礙且修正仍失敗**：保留 Web 筆記／桌面比較；啟動 iOS 原生 P0。手機完整流程仍是未完成，不能標記整體 P0 done。
3. **僅缺匯出路徑**：比較短片本機替代與原生合成，不能直接把合成改選用。不得只為測試通過導入收費後端。
4. **iOS 也沒有完整驗收證據**：繼續列為阻擋，不先投資 Android 或大量 P1。

## 7. #19 手動拍點與倒數（桌面工程候選）

- 原速 BPM 為每分鐘來源音樂拍數，允許有限數值 20–300；不是慢放後重新估計的 BPM。第一拍 `F` 是老師來源時間內的非負整數毫秒，`0 ≤ F < durationMs`，可用當下畫面定位或手填秒數（保存至最近毫秒）。A、B 與自拍 offset δ 維持第 4 節含義。
- 來源位置 `s ≥ F` 的拍序號為 `floor((s-F) × BPM / 60000)`，八拍組為 `floor(index/8)+1`，組內拍為 `index mod 8 + 1`。F 之前顯示「第一拍之前」，不猜負拍或音樂前奏。來源每拍 `60000/BPM` 毫秒；r=0.5／0.75／1 時每拍實際間隔為 `60000/BPM/r`，同一來源位置永遠同一拍。
- 保存 Video 的 BPM／第一拍後，老師播放位置及標記清單附上八拍標籤；原始秒數與筆記不改。暫停、seek 與 A–B 直接重算來源位置，不依播放了幾秒累加。不是自動拍點偵測，也不在原片／VS 烘焙字樣。
- 倒數選「秒數」或 4／8 拍（含提示音）。拍數倒數的實際總長 `N × 60000/BPM/r`，用上方固定錄影速度，與獨立練習速度無關。老師停在 A；從倒數第一聲到開始相隔 N 個間隔，最後一聲與開始也相隔一拍。不自動把 A 移至第一拍；需要音樂第 1 拍起跳，先自行把 A 設在對應八拍邊界。
- 音訊由錄影點按後沿用既有啟動規則，第一聲 880Hz，其餘 660Hz、各 60ms 包絡。預排提示音與文字讀同一音訊時鐘；不逐拍累加計時器。完成才開始錄製與老師播放，提示音不接影片音軌。原生啟動延遲仍按第 4 節觀測與校正，不能把倒數當取樣級同步保證。
- 錄影／倒數中沿用全控制鎖；取消、背景、音訊中斷停止並清理提示音，保留舊自拍、配方與可恢復資料。未保存拍點先明確保存或取消；無可靠拍點可移除，原 3／5／10 秒路徑保持可用。

來源音樂 BPM 有變化時，此版固定 BPM 不足以跟隨整片，請縮短練習片段或使用秒數。自動辨識、變動拍速及量化／snap 另行設計。本候選僅有合成驗證，真人、實體相機與聲音路由未驗證。


Safari本機音訊續修：錄製同步接受後立即供給原音訊與正式影格，不等待可能依賴這些資料的非同步start通知。仍以原偏移護欄、成檔讀回及完整覆蓋判斷成功；通知抵達或start回傳本身都不是完成。私有兩個引擎短回歸支持此候選，正式完整矩陣與十輪須在凍結版本上另跑，原門檻不變，詳見TECHNICAL第36節與同一證據文件。


Safari WebM續修只在有界本機音訊VS不帶timeslice，一次收檔；相機與普通Chrome仍保留逐秒chunks。所有新VS在替換／保存前以未取整的原生讀回片長核對配方共同區間，差超過原100ms即拒絕並保留前次VS。這只補必要片長保護，完整首尾覆蓋與原v5各門檻仍須獨立驗證，詳見TECHNICAL第37節。


### #119 續作：Safari 錄影的播放聲路

Safari 在錄影期間保留示範元素的音高設定並暫時靜音，使用同一原片 A–B 的有界本機 AAC 聲音以 r 自然變調播放；一般練習仍保持音高與原音量。聲音準備完成、以真正影格暖機並回到 A 才進倒數，相機開錄仍早於正式示範啟播；不延後開錄、不在 B 補 seek、不修改 B、片長或 ±100ms。支援格式、取消／故障保全及排除方案見 TECHNICAL 第 51 節，原生結果見 [#9 續修證據](evidence/issue-9-capture-recovery.md#119-續作錄影聲路與一般練習音高)。此續修不代表真相機、聽感、私人模式、背景或完整 G1–G7 已驗收。
