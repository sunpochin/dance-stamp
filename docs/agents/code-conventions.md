# 程式與狀態管理

本文件補充 [AGENTS.md](../../AGENTS.md)，按修改範圍閱讀；不要求為符合慣例改寫整個產品。

## 分工與局部理解

- 新檔用繁體中文檔頭交代用途、所在層、主要關聯；JSON、產生檔與第三方原文維持格式及來源。
- 函式與模組按責任分工。先找既有資料、時間映射與媒體工具；不因檔案很長就拆成無意義的 wrapper，也不為一行排版增加抽象。
- UI 表達意圖，資料驗證、交易與媒體生命週期使用既有模組；重用相同規則，避免畫面各自處理另一套時間或保存邏輯。
- 改共用函式先查所有呼叫端及對應測試。非直覺順序、失敗保全與取捨用繁體中文原因註解說明。

## 狀態與非同步順序

- 讀取與保存的進行中／錯誤狀態分開，避免讀取失敗被顯示成保存失敗，或舊成功訊息蓋掉新錯誤。
- 同一組操作狀態由同一個 owner 管理，提供選片、確認、停止等語意操作；不把框架專屬 hook 或固定狀態數量當成拆分條件。
- 延遲 callback、計時器及 Promise 回來時，核對它仍屬於目前的操作／版本。新操作不能被舊結果改寫；取消也不能以「不再等待」冒充底層已停止。
- 相機 tracks、播放器、object URL、影格訂閱及監聽器各有明確 owner。依既有取消／失敗／離頁契約清理，不以清空資料或提早撤銷舊 URL 修掉競態。
- 儲存失敗與是否提交未知要分清楚；先保留原片、筆記與可救援內容。交易與保存尾段的特例依 [TECHNICAL.md](../../TECHNICAL.md) 和既有程式，不套用一律 abort 的簡化。

## 變更後

跑受影響的既有測試與 `bun run check`，檢查成功、失敗、取消及同頁重試；媒體與儲存另外依 [工作流程驗證矩陣](workflow.md#驗證矩陣)。
測試抓到問題時先確認根因，不以減少斷言、加寬門檻或刪掉失敗案例換取通過。
