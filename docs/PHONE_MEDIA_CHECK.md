# #3 手機媒體實測

這份清單需要你操作自己的手機；桌面假相機、畫面尺寸模擬與 API 偵測都不代替這些結果。先測主要使用的一台，再補另一台較舊 iPhone；Android Chrome 為次要。數字依 [G1–G7](RECORD_COMPARE.md#5-先做的可行性試驗與決策門檻)。

目前桌面 G3 發現約 264–268ms 的合成停格，詳見 [本輪證據](evidence/issue-3-media-feasibility.md)。**現在先做步驟 1–7 的 15 秒 1× 與保存測試即可；步驟 8–12 的完整矩陣留待 G3 修正後再跑。** 首輪提供手機平台差異與保存路徑，不代表手機已驗收。

## 電腦先準備一次

使用本 PR 的版本與 Bun 1.4.4，保持電腦與手機在同一個可信任 Wi-Fi。此入口只供短期區網測試，沒有對外部署。已存在測片／憑證時不要重跑產生器，也不要刪掉原證據來重跑。

```sh
bun install --frozen-lockfile --ignore-scripts
bun run build
python3 scripts/make-sync-fixtures.py
python3 scripts/prepare-phone-preview.py
```

產生器讀取 macOS 目前網路介面的 IPv4；若網路選錯，可明確傳入手機能連到的區網位址，例如 `python3 scripts/prepare-phone-preview.py 192.168.1.20`（僅為範例）。它保留七天有效的測試 CA 與伺服器憑證在 ignored `output/phone-preview/`，不安裝信任、不修改系統設定、不覆寫舊憑證。只將 `ca.crt` 透過 AirDrop 傳到自己的測試手機；私鑰 `.key` 留在電腦，不加入 Git／issue／PR。

按產生器顯示的「啟動」命令啟動 HTTPS 預覽。伺服器只提供固定應用資源與這支合成測片，不接受上傳或任意檔案路徑。桌面測試可另用 `DANCE_STAMP_PORT=42833 bun --no-env-file scripts/serve-web.ts`，避免佔用其他工作的預覽。

## 你在 iPhone 做的操作

1. 記下 iPhone 型號、iOS 版本；測試記錄同時填本 PR commit。Safari 跟隨 iOS 版本。先用喇叭，之後另測藍牙。
2. 安裝剛收到的 `ca.crt` 描述檔，並到「設定 → 一般 → 關於本機 → 憑證信任設定」啟用這張測試 CA 的完整信任。只信任本次由自己電腦產生的憑證；測完移除描述檔。安裝描述檔與啟用 SSL 信任是兩個步驟，見 [Apple 說明](https://support.apple.com/102390)。
3. Safari 開啟產生器顯示的 `https://電腦位址:42835/`。若仍出現憑證警告，先修好信任／Wi-Fi／位址，不能把不安全來源造成的相機缺失當成 Web 媒體失敗。
4. 在相同位址的 `/test-reference.mp4` 下載合成示範片到「檔案」，回工作台按「示範影片」選它。測片有每秒閃光、提示音與逐幀編號，無真人／第三方音樂。
5. 第一輪設開始 0 秒、結束 15 秒、速度 1×、倒數 3 秒。點「開啟前相機」並允許相機；預設不要求麥克風。確認取景正常，再點「倒數並錄下我」。停止後確認相機使用指示熄滅，立即下載自拍原片。
6. 用「自拍偏移」手動對齊，分別試正／負微調及兩側鏡像；「一起預覽」核對後，按「輸出單一 VS 影片」。記下從開始合成到完成所需時間。
7. 下載 VS 到「檔案」，離開工作台，在「檔案」重新開啟；核對左／右畫面、鏡像、完整構圖、長度、提示音只有一份。再分別嘗試系統分享、儲存到相簿，逐項記成功／失敗，不能因存到「檔案」就填相簿成功。
8. 以上成功後完成下表。每輪先保存原片／VS／筆記，再重新選示範，設定對應的終點與速度。take 的實際長度是 `(結束−開始)÷速度`，不是原片秒數。

| 實際錄影長度 | 0.5×：開始／結束 | 0.75×：開始／結束 | 1×：開始／結束 |
| --- | --- | --- | --- |
| 15 秒 | 0／7.5 秒 | 0／11.25 秒 | 0／15 秒 |
| 30 秒 | 0／15 秒 | 0／22.5 秒 | 0／30 秒 |
| 60 秒 | 0／30 秒 | 0／45 秒 | 0／60 秒 |

9. 同一手機、同一 Safari 模式，以 1× 連續十次完整執行 60 秒「錄影 → 原片保存 → 校正 → VS 合成 → 下載／重開」。使用同一資料庫，不清除網站資料；每輪核對舊 take 仍可開啟。記錄失敗輪次、熱感、電量前後、空間不足及有無資料遺失。
10. 在完成備份後，分別測倒數取消、錄影中停止、合成中取消、切背景、鎖屏、旋轉與相機被其他 App 占用。確認有可理解結果、相機釋放、上一段成功原片／輸出仍可下載；中斷片不一定可解碼，不能填完成。來電可在方便時另做，未做填「未驗證」。
11. Safari 分享選單「加入主畫面」，啟用以 Web App 開啟（若系統提供），從圖示開啟後記錄實際模式並重做以上核心流程。Safari 分頁與主畫面模式分開填結果；離線與跨模式儲存不互相推定。
12. 換藍牙再驗證來源音訊、錄影與輸出；有 HEVC／MOV、直向、旋轉資訊或 HDR 的自有測片時另列格式結果。原檔留本機。

## 其他需要你操作的項目

這台 Mac 的 Safari 若要由 Agent 補自動化，需你在 Safari「設定 → 開發者」開啟「允許遠端自動化」（Safari 27 可能顯示「Allow remote automation and external agents」；版本不同時可能需先顯示開發者功能），見 [Safari 27 官方說明](https://webkit.org/blog/18325/webkit-features-for-safari-27-0/)。本次不自動改設定。真正相機權限／實體鏡頭、LED、音高聽感與背景行為仍須人工確認。

Android Chrome 可先測相同核心流程，安裝 CA 的路徑依系統而異；先記錄裝置與系統，不把 iPhone 結果複製過去。裝置缺少、未啟用設定或沒有可信 HTTPS 都填未驗證，不觸發 iOS fallback。
