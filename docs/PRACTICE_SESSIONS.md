# 自主練習回合 Practice Sessions

[#259](https://github.com/sunpochin/dance-stamp/issues/259) 保留為 P1 提案，尚未排入實作。原先的「每天練哪段」縮小為回顧時的一個選擇：下次想再練哪段？

## 已確認方向：為下一場舞會準備一個動作（2026-11-04）

白話：先想一個下次舞會想用的課堂動作，在住處或選定的練習地點把它練到有機會用出來，再到舞會繼續熟悉。使用者已同意先以這個方向探索「怎樣才願意開始練」，並補充首先需要一個此刻願意花時間練的理由，幫自己開始動起來。提醒帶出自選動作與本人認同的理由；2026-11-05 已確認把起步與熟練分開：準備好後慢速跟跳自選 8 拍一次就算有開始，練出目標則是不用一直看示範，也能跟所選影片的原速音樂跳完整段一次，由本人判斷。首次先觀察下一次流程的送達、實際跟跳與卡點。下方原有完整回合／歷史流程仍是候選，尚未證明能促成這個結果。

### 兩個時機需要不同幫助

使用者進一步提出兩種需求：還在滑手機、尚未進工具時，需要有人提醒停下來想起練習；進工具後，需要手把手帶著完成準備。這裡把兩者稱為「練習提醒」與「開練引導」，定義見[詞彙表](../GLOSSARY.md)。

| 時機 | 舞者需要的幫助 | 尚待確認 |
| --- | --- | --- |
| 尚未進工具 | 本人選下一次開始準備的時間；第一次用 iPhone「提醒事項」手動設定一則文字及日期／時間，收到後再開 Dance Stamp。沒空可延後、改期或這次不練，未回應不追加催促。 | 實際通知送達與操作仍待試用；不能假定工具知道本人正在用哪個 App。 |
| 已進工具 | 先選在住處練、準備外出練或已到練習地點，再依已確認清單逐步準備。按「準備好了」才前進，可略過已完成或不需要的步驟，中途離開保留進度；準備好後開預選的 8 拍，自選先看示範或直接跟跳，也能回到完整目標片段。常用地點存本機，返回可續接或重選情境，新一回重新確認準備。 | 已選可操作的最小試用版，實際手機操作、播放與回饋仍待實作及驗證。 |

白話示意是「想起下次舞會想用的一招 → 開工具 → 選今天在哪裡練 → 做眼前這一步 → 開所選片段，先看或跟跳」。三種情境的準備清單已確認；已換好衣服、已在場地或不需要換裝的人可略過不需要的步驟。閱讀提醒、完成準備與實際跟跳須分別辨認，不把提醒點擊或穿好鞋當成已練。

### 已確認的提醒與引導方式（更新至 2026-11-05）

白話：先由舞者自己約下一次「開始準備」的日期和時間，練完再約之後的時間。提醒帶出想練的動作和本人的理由，例如「週五想要練出這個 shine」；沒空就延後、改期或這次不練，沒回應不再催。開工具後先選在住處、準備外出或已到練習地點，再像有人陪著準備，一次只說眼前一件事；按「準備好了」才往下，做過或不需要的事情可以跳過，中途離開保留進度。

技術決策：Q9／Q13 是舞者自評，不新增 AI 評分；原速完成一次不保證能應付所有舞會音樂。Q10 允許直接跟跳，不把原候選的三輪觀察當成必要前置。Q12／Q22 已選本人手動使用 iPhone「提醒事項」作首次提醒途徑，尚未建立真實排程；網站內排程／Push 仍未實作。示例的「週五」是練習理由中的目標描述，不當成每週五重複提醒。Q14 地點名稱留在本人裝置，不把真實私人地點寫進 repo；Q15 延續進度仍須允許修正當前情境，不能把上回穿鞋直接當成本回已準備好。

Q17 的 8 拍由本人選擇，不從影片秒數或播放次數推定舞步與本人動作；慢速數值由本人調整，不自行新增固定速度。準備、實際跟跳及達成熟練目標分開辨認，Q18 的「我有跟跳」由本人確認，自評／心得可略過，不能以播放完成或準備點擊自動計次。這次接受收尾回饋不等於接受下方舊候選的所有歷史、推薦或備份實作；最小回饋的資料格式與保全驗收留待實作設計。Q16 的單次觀察只找操作卡點，不能當成改善長期習慣的證據。

Q19 的起步區間與完整目標片段需各自保留，挑 8 拍不覆寫原目標；開練前選段是為了減少提醒當下的選擇。Q20 已收斂首次交付範圍，後續實作需沿用現有播放與資料保全能力。Q21 的手機型號為本人提供，不是裝置驗收；尚未取得實際 iOS 版本、通知送達或手機流程證據。

### 帳號與保留進度的界線

白話：選在哪裡練、記住準備到哪一步，不必先註冊 Dance Stamp 帳號。使用者已選第一版先在同一台裝置收提醒與保留進度，像把準備清單放在手邊；換另一台裝置接著準備不列為這一版的完成條件。

技術：沿用核心免登入與資料預設不外傳的規則，先將準備進度設計為同一份本機資料的延續，不新增必要的身分登入。第一次提醒採本人操作的現有手機工具，送達仍須實測，不能把免登入或保存進度當成網站已能在關頁後準時送達。既有 [#209 雲端候選](CLOUD_SYNC_SHARING.md) 以本人明確連接的供應商帳號保存選定資料，不要求另一套 Dance Stamp 會員；新提醒與準備進度尚未定義或納入該封套，不能宣稱既有 Google 連接已涵蓋。本輪不新增帳號、同步或服務。

### 工具外提醒的可行性（技術查證，2026-11-04）

現行產品程式未串接系統通知或其他 App 的使用紀錄。觸發來源已確認為本人選定的下一次開始準備時間；Q21 指定首測 iPhone 17e，Q22 因既有 Google Calendar 可能太複雜而選擇先用 iPhone「提醒事項」手動試一次。工具已選，通知送達與操作負擔仍待實測。Web Push 留作後續可能方案，本輪未建立排程或新增服務。

- [MDN Notifications API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API) 說明通知由作業系統顯示，需使用者授權；手機應使用 Service Worker 的持續通知。這只說明能在其他 App 前顯示通知，不表示網站得知對方正在滑手機。
- [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API) 說明標準 Push API 可接收伺服器傳來的訊息，包含網站不在前景或未載入時；送達來源、排程與訂閱處理都還要設計及驗證。
- [WebKit 的 iOS／iPadOS 說明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/) 列出加入主畫面及由使用者操作申請權限的要求。這是文件查證，非本產品手機通知已驗收；也不因此把 iOS 原生 App 列為前置。
- 人工提醒有現成能力：[Apple 提醒事項指南](https://support.apple.com/en-au/guide/iphone/iphec7a1de82/27/ios/27) 說明可加筆記、連結與日期時間，部分功能依其帳號類型而異；[Google Tasks 建立說明](https://support.google.com/tasks/answer/7675838?co=GENIE.Platform%3DAndroid&hl=en) 與[通知設定](https://support.google.com/tasks/answer/13486720?co=GENIE.Platform%3DAndroid&hl=en) 說明日期時間及通知權限，亦列出系統可能延遲通知。這些是人工試用途徑的查證，不代表網站可自動寫入，也不代表供應商完全免帳號、已整合或準時送達；Q22 已選 Apple「提醒事項」，Google Tasks 僅保留為先前查證。

原候選下方的「沒有推播」描述先前產品範圍。首次試用的人工提醒不需要新增網站推播；通知是否收到及是否促成開練仍須各自觀察，原候選不能代替這個新需求的驗收。

2026-11-05 已選的首次提醒方式：用 iPhone「提醒事項」只建立一則標題與明確日期、時間，例如「為週五的 shine，先開始準備、跳 8 拍」。[Apple 官方操作說明](https://support.apple.com/zh-tw/102484)確認可新增文字並自訂日期與時間；只選日期而不填時間會使用整日通知的預設時間，因此不能省掉本人約定的時間。Q22 已接受先試一次，尚未實際建立；不把選用工具當成已證明操作更簡單，仍需觀察設定與切換 App 的負擔。此處不要求搬移原有 Google Calendar 行程，網站也未取得任何日曆寫入權限。

### 匿名訪談線索與適用範圍

- 一位受訪舞者描述，曾因近期舞會有實際用招及與舞友互動的機會，而在家先練；疲累時，知道練習有價值仍不保證會開始。
- 該舞者認為，先在家練到能用，才有機會在舞會用出來；舞會中的反覆運用有趣且有幫助。兩種情境都屬於練習，不能據此推定舞會能取代居家準備。
- 課堂動作在舞會用得出來、獲得舞友回應，是這次訪談出現的動機線索。它們尚未經前瞻試用，也不能推論其他學生有相同動機。

### 行為設計對照與審查（2026-11-04）

白話：提醒幫人想起要練，自己的舞會目標讓練習有理由，一次做一步減少不知道怎樣開始的困難。這些與《原子習慣》的方向相通；還需要觀察人是否真的開始跳，以及跳完後是否願意再來。懂得這些方法，不代表這個產品已經有效。

當時回看 PR #266 的 `e5a3bb835fd7c57ee71ae3a0fac3364f56d09ad1` 相對來源基線 `9cf6db7960bbdcd5c8b560e32b68a49f225c5c2a` 的五份文件，未發現阻擋需求紀錄的問題：已確認選擇、未決事項、舊候選與未實測效果有分開。這是原撰寫者的回看，不是獨立審查核准，也不涵蓋後續增補。當時 Q13–Q16 與小起步／回饋建議尚未決定；使用者已於 2026-11-05 接受 Q13–Q18，以下對照更新其需求狀態，研究本身不當成產品效果證據。

[James Clear 的四法則](https://jamesclear.com/atomic-habits-summary)是作者整理的行為設計框架；以下對應是本提案的設計判讀，不是研究直接驗證本產品的結論。

| 框架方向 | 本提案的對應 | 還要留意 |
| --- | --- | --- |
| 讓提示明顯 | 本人選定的時間與手機提醒。 | 收到提醒與開始練習要分開觀察。 |
| 讓行動有吸引力 | 本人想在週五用出所選 shine 的理由。 | 這是個人動機線索，疲累時未必足以開練。 |
| 讓起步容易 | 預選片段、可略過的單步準備、同裝置免 Dance Stamp 帳號；慢速跟跳自選 8 拍一次就算開始。 | 清單本身也可能多出操作負擔；8 拍是否足夠容易仍須試用。 |
| 讓完成有滿足感 | 確認「我有跟跳」，可選練後感受與心得；舞會用招仍是較晚的期待。 | 是否真的有滿足感與願意再練，需要本人試用；不能由按下回饋推定。 |

技術依據與適用限制：

- **明確情境接明確行動**：實施意圖（implementation intention）把「想做」寫成「遇到某情境，就做某動作」。[Webb 與 Sheeran（2007）](https://www.sciencedirect.com/science/article/pii/S002210310600028X)的文字作業實驗支持這種線索與行動連結；不是舞蹈產品試驗。目前只約時間、進工具才選情境，尚不能視為完整的個人 if–then 計畫。
- **小起步與熟練目標分開**：[Clear 的兩分鐘法則](https://jamesclear.com/how-to-stop-procrastinating)主張縮小開始的動作，不是兩分鐘內學會技能。已接受的 Q17「準備好後，慢速跟跳自選 8 拍一次」與「週五練出整段」分開；不是把換鞋或點完清單計為練過，也不表示這個起步已證明適合所有舞者。
- **長期習慣需要重複觀察**：[Keller 等人（2021）](https://pubmed.ncbi.nlm.nih.gov/33405284/)將 192 位成人分到日常活動線索或時間線索，觀察飲食行為 84 天；兩組的自動化程度與計畫執行情況均增加，組間未見差異，反覆執行計畫是自動化的重要預測因子。這支持之後觀察反覆在提示下開始的可能性，不要求現在改成固定作息，也不證明時間提醒一定讓舞者養成習慣。

原審查提出的兩項缺口已由 Q17／Q18 確認試用方向：最小實際跟跳，以及練後由本人確認有做並可記下感受。不新增打卡、獎懲或強制自評。首次流程觀察可找卡點；是否更常開始、是否逐漸不用費力提醒、是否練熟，仍是不同問題。單人訪談中的同意只能確認偏好，不能證明介入成效。

## 一回怎麼練

> **今天把這 8 拍練熟 · Shine 第 3 段**
>
> 00:18–00:26 · A–B 循環 · 0.75× · 預計五分鐘
>
> **1/3　觀察**　先看老師示範三次，留意腳步方向與重心。
>
> **已觀察，開始跟跳**

這是畫面文案示例，五分鐘是舞者給自己的時間。「8 拍」是舞者自己選的名稱。無拍點也能用原片秒數圈選，系統不從秒數推算舞步。

| 階段 | 舞者操作與回應 |
| --- | --- |
| 進入 | 從正常桌面首頁選一支有權使用的示範片，手動設 A/B 或選既有區間標記。單點標記需補終點。在已保存片段、原片可用時，一次點「開始練」就從 A 播放，無須事先建計畫、選第二支影片或登入。 |
| 1 · 觀察 | 慢速、鏡像與 A–B 沿用現有練習播放。例中完整播三輪後停回 A，等舞者按「開始跟跳」；可提早切換或再看。暫停、跳轉或播放失敗不算一輪，不推定人已跟跳。 |
| 2 · 跟跳 | 同段反覆播放，舞者可調速、鏡像、暫停或結束。錄自己是明確點選的選項，符合既有錄影條件才依 #9 啟動。拒絕授權、中斷或片段不合條件時仍可繼續跟跳與回顧。 |
| 3 · 回顧 | 舞者確認「我有跟跳」，可選「還不熟／比上次順／這段先放下」，也可略過自評。有錄影可回放自己的錄影；沒錄影也能保存這一回。只看示範、提早離開或按兩次儲存都不增加跟跳回合數。 |

**Practice Plan 的角色。** 回顧時可按「下次再練這段」。下次開啟先顯示手選片段，否則建議最近一次自評「還不熟」的片段，並說明理由。用每段最新自評，已改選「先放下」或「比上次順」就不繼續以舊自評推薦。沒有候選就讓舞者選段。可忽略或換段，缺片時提示重連。第一版沒有日曆、每日待辦、連續打卡、XP、排行榜、AI 評分或推播。

## 同一段的第一次與第五次

- 每個已存片段有穩定 ID、來源影片、段名與 A/B 快照，每個回合連回該片段；Marker 僅是選段來源。修改或刪除 Marker 要提示並保留原片段，改練不同 A/B 時另存片段，避免兩段的進步混在一起。A/B 必須是原片整數毫秒且滿足 `0 ≤ A < B ≤ 影片長度`。
- 同段的歷史依時間列出舞者自報有跟跳的回合、當時速度、自評及可選的 take ID。可直接選例如「第 1 回」與「第 5 回」，依序回放兩次自己的錄影並看到各自的感受。某回沒錄、錄影已刪或原片待重連時照樣顯示該回，指出缺哪一份，不拿別回頂替。
- 首版驗收的是從自己的歷史直接取回兩份原錄影。老師與自己的比較沿用既有配方；把兩次自拍重新對時、並排或合成另一支 VS 等需求，另依 [錄影比較規格](RECORD_COMPARE.md) 評估。拿掉錄影連結不刪回合，刪回合也不連帶刪媒體或既有比較。
