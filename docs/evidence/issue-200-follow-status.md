# 單側結果成功後顯示正確提示（#200）

## 怎麼用、為什麼有效

框到空白或製片失敗時，可以保留原片與筆記，在同一頁重新框選或更新結果。成功後上方會說「老師跟隨影片已完成」或「自己跟隨影片已完成」，不再一邊顯示新影片，一邊留著前次失敗訊息。取消與真正失敗仍會告訴你原因，舊成果保留。

像影片已做好，負責報消息的人卻還拿著上一張失敗紙條；現在由兩個入口共用的成品交付點通知主畫面。只有新檔確實交換成功才換提示，不在開始操作時先宣稱完成。

## 原始觀察與主線紅燈

Safari27.0.1／macOS27.0.1在固定f1da093的原生驗證中，第一次跟隨逾時後，鍵盤重試已產生兩側有聲影片，全頁仍保留舊逾時訊息。這份觀察及啟動資格未知原因仍歸屬[#194固定版本證據](https://github.com/sunpochin/dance-stamp/blob/47c2689d436095b34bcce33db100bfee34e36a18/docs/evidence/issue-194-follow-audio-activation.md)，不改標為本票通過。

本票從同步main `148f5845d52a9433dcd97274feb45edb35e40c79` 建獨立分支，不接入#198的音訊變更。先只修改既有`follow-results`回歸：用可見選框欄位選0／0／5／5%的空白角落，真正人物模型回報未找到人物，再在同一頁用正確選框重試。沒有偽造成功、直接寫狀態或呼叫內部handler。

未修產品時，回歸確實在「成品已成功卻仍顯示舊錯誤」拒絕；當時可播放結果已就緒，全頁仍是「選框中未找到明確人物…原片仍保留，可重試」。原始紅燈、來源十四檔及完整收據保留，0頁面例外；主機／瀏覽器正常關閉並釋放自有鎖。

## 修正在成功交換點

`main.js`繼續擁有全頁`status`，將既有函式傳給`createFollowUI`。`publishResult`在新播放器與下載URL完成交換、舊URL按原順序釋放後，通知主畫面正確一側已完成；首次分析與更新結果共用，不各寫一份分支。

排除在共用`operation`開始或finally清空訊息：開啟選框不等於製片成功，清空也可能蓋掉真正失敗、取消或儲存警告。沒有新增狀態旗標、計時器、常駐音訊環境或第二套下載流程；原音訊、模型、8Hz、時間映射、像素／片長與期限不變。
