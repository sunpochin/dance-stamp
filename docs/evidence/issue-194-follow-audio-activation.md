# 單側結果的音訊啟動與保全（#194）

## 怎麼用、為什麼有效

照原流程選兩支影片、設定比較片段，框選老師或自己後按一次確認即可。像先把聲音的門打開，再找人物：分析花比較久時，製片仍可接手同一個已準備的音訊環境。按取消或遇到失敗會關掉本輪資源，原片、配方和上次成功影片仍保留。

本票只處理單側結果的啟動時機及收尾。仍需下載並離開產品重播，才能確認成品能獨立使用。以下固定版本的根因對照不能直接當成後續產品候選、真人或實體裝置通過。

## 原生失敗：等待確實卡在音訊

受測來源 `fcd124d6845ddc3cd9ab705cf2049486911e97ad`，靜態 `15c42b365938118a`；macOS 27.0.1，Safari 27.0.1（22625.1.29.11.28）一般新視窗。使用 AI 虛構成人及自製660／880Hz音訊的四秒合成片，老師0.4–3.4秒、自己0.5秒起跳，共三秒；老師框選3.5／2.5／37／95%。沒有相機、麥克風或站外上傳。

一次真正確認後，25／25格已分析、追蹤完成：分析5431ms、單側製片15073ms、總等待20505ms，仍出現「等待影片準備逾時」。185筆有限旁聽沒有丟棄；確認時為trusted手勢，5503ms後的音訊resume呼叫已無暫時啟動狀態，context維持suspended／currentTime0。15001ms後原statechange等待才被移除並關閉，沒有resume成功、拒絕或running通知。

來源影片已loadeddata／readyState4／960×540／error0；尚未呼叫來源play、建立音訊destination或canvas擷取。因此這次實際逾時位於音訊啟動，並非模型未完成或開始製片後的畫面停滯。原生另存schema2報告1380bytes，SHA256 `7190a57c0be32ad789b2b001aca71492d4fa6a536e5ab2ccfd8fe54aa136a2c8`。

取消後完整library、媒體、原片及結果播放器與控制值均與準備前相同，0結果、0頁面例外、0硬體呼叫。自有視窗／主機正常收尾並核對nonce釋鎖；原日常頁保留。90檔／23,864,450bytes獨立封存readback一致，manifest SHA256 `687c139c6cdd61a7e86dfcf13f15fa618bc8ee6177847c45eaf50edf45411b00`。更早首次失敗、耗時報告及不同的直接API100ms失敗亦維持原版本與原結果。

## 單一時機對照：同一真正環境提前啟動

仍用上述固定產品來源、同一合成輸入與選框；僅診斷入口在trusted確認內建立並resume原生AudioContext，再把**同一個真正物件**交給未改的製片函式。沒有偽造running或resume承諾，沒有連接影片DOM、增加影格請求或改PCM、門檻與期限。共用鎖原子取得，第一次產品確認即完成，未重試替換結果。

- 原生resume在1024ms後running；5437ms後交給製片時，暫時手勢已結束但同一環境仍running。人物25格全完成，分析5368ms、製片3243ms、總等待8615ms。
- 真正原生另存影片519,233bytes，SHA256 `f5fe1f15e45e32fccf2b3f0406a7f6287d72b1ca213d41a260d7af80100386f7`，VP8／Opus、354×512。schema2耗時JSON1377bytes，SHA256 `9ec8acbc4b386f0767e79c95a8e95879b88e7c1caaabfc018d4f6eb7c6d0a3c8`。
- 產品視窗、主機停止後，另開離線Chrome156.0.8078.76的原生file播放器：自然ended、3.008秒、96 frames／0 dropped／error0、audioBytes71675；只有file請求。完整影音解碼exit0、stderr空，檔案hash不變。
- 沿既有音訊量尺：FFmpeg取0.3秒後一秒、單聲道8kHz float32，660Hz強度除以max(1,880Hz強度)為499531，原門檻>20通過。另存的48kHz長窗Goertzel比例僅為追加診斷，不當成原音訊門檻的數值。
- 原片播放器位置、完整library與媒體均不變；0硬體呼叫、0頁面例外，單一音訊環境closed、三條擷取track ended。自有主機exit0、連接埠拒絕；獨立播放器所有已知PID退出、兩段自有nonce均釋放。

95檔／24,643,374bytes的控制流程、真下載與固定來源已獨立封存readback一致，manifest SHA256 `79d8b73232a225f54c9a48c723d45c37b122df035198e5142fa6e681c837f6ac`；原8kHz量尺收據另保留。這是單一老師對照，不能代替候選程式的兩側、鏡像、取消／重試或完整G1–G7；也沒有替原#11的130ms失敗改標。

## 候選修正與回歸

從同步main `19e7c12d24a91586c6ca88ade40c51fcc860a58c` 建立本票分支。確認及更新入口在手勢內先準備同一音訊環境，分析與聲音準備並行，成功後交給原export；介面負責尚未交付時的取消／失敗／未開始清理，原export保留已交付的finally。設計與排除方案見TECHNICAL的本票段落。

新增順序回歸先對**未改產品**執行，選定follow-results原生輸出完成後因實際順序「confirm → Worker → AudioContext建立 → close」而失敗；該輪來源即上述main、產品十四檔hash未改，自有瀏覽器／主機／鎖正常收尾。沒有改原音軌、像素、時間、取消、資料或期限斷言，首輪紅燈完整保留。

候選產品十四檔hash固定，僅follow-ui／follow-export兩檔與main不同，靜態版本`0c7a4d8036053101`。一般check通過：694單元／0失敗／3690斷言，型別、lint及建置通過（原19項info保留）。本機選定四案person-follow、follow-results、webkit-follow-results、follow-performance全部通過、0頁面例外，瀏覽器／主機停止、自有鎖正常釋放；這是局部矩陣，不能寫成完整77案。

兩條供聲路徑都實際記錄trusted確認→context建立／resume（手勢仍有效）→Worker→close，兩側各自正確音軌；660／880Hz的原強度比502099／502477與473327／484276，均超過原>20。原像素／鏡像、片長、停止、待決resume取消、編碼失敗、換片及library斷言保留；新增分析取消、Worker建構失敗與真正context的控制resume拒絕，也都關閉音訊並保留兩份舊下載。失敗注入屬受控回歸，不宣稱自然原生故障。

主機及測試瀏覽器停止後，另開離線Chrome156.0.8078.76原生file播放器，重播該輪兩條供聲路徑各三份真正下載（老師／自己／老師鏡像）共六份：全部自然ended、error0、0dropped、audioBytes>0，片長2.993667–3.020751秒。每份一條影像／一條音訊，FFmpeg全軌完整解碼exit0、stderr空、hash未變；只有file請求，已知自有PID全退出並釋鎖。這證明候選來源的Chromium成品可獨立使用，不當成Safari或真人聽感驗收。

這輪選定回歸執行時尚未提交，來源為上述main加本票變更；交付須再核對提交後十四檔與測試hash一致，不能將髒來源改稱已在乾淨新head重跑。完整77案CI尚待PR執行。真正原生Safari候選流程因Mac螢幕鎖定而尚未啟動，已請使用者手動解鎖；沒有占用QA鎖或開啟候選主機／視窗等待。原生兩側、鏡像、取消／失敗保全與下載離站播放仍未驗證，保持草稿與本票開啟；上述固定來源對照不代替候選或實體裝置通過。合併與發布另需明確授權。
