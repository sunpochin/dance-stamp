# #103 背景程式載入失敗的恢復與保全

## 怎麼用、為什麼有效

找人的助手如果沒有成功載入，畫面應告知「無法啟動本機人物分析」，停止等待並保留原片、配方與上次成功的跟隨影片。載入問題解除後，可以在同一頁重新框選分析，不必清空資料或重開頁面。

這次只補現有保護的測試：先真的做好影片，再中斷一次背景程式的載入，檢查舊影片還能下載；恢復載入後，找人與製片仍須完整成功。像助手沒進門時，先回到可以操作的畫面，不能把舊成果一起丟掉。

## 範圍與方法

- 從同步 main `148f5845d52a9433dcd97274feb45edb35e40c79` 建 `codex/issue-103-worker-load`，沿用 `follow-runtime`。十四份產品 JS、計數器及分母不變；未帶入其他未合併 PR。
- 原九種 SIMD／相容／回退／建構失敗／初始化取消案例與相對順序保留，最後追加一次背景程式請求中斷與一次同頁重試。完整輪仍為原 78 個情境名稱／順序。
- 沿原預設介面、本機模型、虛構人物合成片與 8Hz／25 格要求。原成功 180 秒、失敗／取消恢復 15 秒及產品偵測 30 秒期限不改。
- 使用既有隔離瀏覽器資源控制，僅中斷一次真正 `person-worker.js` 請求；沒有派送 error、呼叫內部 handler、替換模型結果或改動 CSP。觀察者只記錄原生錯誤的 `isTrusted`／type，不攔截或取消錯誤。

本案沿既有 `follow-runtime` 的 Service Worker 阻擋環境，確保受控資源錯誤確實到達請求邊界。這是載入中斷的合成控制，不是自然網路故障、離線快取損壞或原生 Safari 的重現。

## 驗收契約

1. 請求中斷後，只建立並釋放一個 Worker，收到一次可信原生 error；未回退重建、未完成任何推論／追蹤格。
2. 畫面與選框對話框都保留真正失敗原因，並在原 15 秒恢復期限內可以操作；原片位置、完整當前 library 與舊跟隨開關／下載連結相同。
3. 從真正下載入口另存故障後的舊影片，完整長度及 SHA-256 與故障前最後成功、已真正下載的相容回退成品一致。保留原三種成功模式的下載清單，新增保全檔另記，原 CI 離站播放檢查不被替換。
4. 恢復背景程式請求後，在同一頁重新分析。原 SIMD 模式成功，25 格、一次 Worker 且完整釋放；新成品交換、原片與資料不變，沒有殘留原生 Worker error。

## 結果與限制

macOS arm64、Bun 1.4.4、Chromium 156.0.8078.76：乾淨主線原案九種邊界 35,543ms 通過；加入載入中斷及重試後十一種邊界 40,362ms 通過，0 頁面例外。只有新增失敗輪收到一次 `isTrusted: true` 的 Worker error；其餘十輪沒有 Worker error。每輪建立的 Worker 全部終止，原片位置及完整當前 library 相同。

受控載入失敗的分析／整輪計時皆 1.7ms，零推論／追蹤格、一次 Worker、零回退，沒有把失敗計成成功暖輪。這是本輪診斷碼表，不能外推成使用者等待或網路效能門檻。同頁重試 25/25 格、SIMD 一次 Worker；分析 1454.6ms、製片 2998.7ms、確認後整輪 4456.7ms，原資料與位置不變。

同十四份產品 bytes、同一情境、相同 statementMap／fnMap／branchMap：`follow-ui.js` 函式由 44/63（69.84%）到 45/63（71.42%），新增命中原第 221 行 Worker error 回覆；行數 196/221、分支臂 145/240 均不變。這是局部對照，不與別輪相加，不代表完整 App 或 100%。來源如實記為 `148f584` 加未提交測試；提交後核對產品及測試指紋，不移記為提交後已重跑。

故障後真正下載為 405,196 bytes，SHA-256 `ac3fe2102068523bcfc62a5c439841fef104dc353001b3faeaa550b51f4170df`，與故障前最後成功下載逐 byte 指紋一致。產品及原瀏覽器關閉後，另開離線 file 播放器重播原三份 runtime 下載與這份保全檔：四份全部自然 ended、error 0、有音訊、全軌完整解碼、檔案指紋不變。自有播放器的已知 PID 全退出、nonce 鎖釋放；原始收據及檔案只留本機忽略目錄。

獨立審查、真人／聽感、實體裝置、原生 Safari、冷網路效能、快取損壞及完整 G1–G7 未由本案驗收。#103 保持其餘缺口，沒有合併或正式發布。
