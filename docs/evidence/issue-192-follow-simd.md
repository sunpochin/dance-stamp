# #192 整合版人物追蹤與 SIMD 對照

## ELI5：同樣八張照片，換更快的計算工具

先用現在整合好的版本量一次，再用同一支合成片、同一台電腦試 SIMD。每秒仍挑八張，跟人的規則也一樣；只讓每張照片的計算能成批做。不支援或初始化失敗就換回原工具，取消或失敗保留上次影片。

## 技術：來源與實驗設計

- 整合版基線固定 `83caa373ee2238db5d8d4a9857ba93318671471b`，靜態版本 `15c42b365938118a`。基準開始時工作樹乾淨，使用未修改的已合併工具與產品。基準期間只寫候選來源，不建置、不替換該輪dist，受測頁面始終為原靜態版本。
- 先量老師／自己10／30／60秒，各兩輪；另留兩輪關閉計時對照。分析、單側製片與總等待分開，原#176的schema1比例不移記。
- 後續交錯對照複製原基準影片 bytes，驗SHA、960×540、30fps、60秒及0／10／20／30／40／50秒關鍵格。兩個runtime使用同一套旁聽工具、相同快取、選框、8Hz與順序配置；每輪新Worker，不平行推論。
- 幾何旁聽只保存合成片數字，不保存像素。使用產品原matchPerson／followBox／smoothTrack還原路徑，先核對搜尋框與真正製片裁切，再逐格一對一比偵測框、失聯數、格數與路徑。模式間每座標差不得超過一個來源像素；原聲畫／片長／取消門檻不變。交錯對照總分析至少改善10%且每輪都縮短，才採用候選。

## 相容回退與保全設計

固定 `@mediapipe/tasks-vision` 1.2.0／EfficientDet-Lite0 int8／CPU delegate。使用套件官方能力檢查；不支援或檢查失敗直接選非SIMD。SIMD的載入／初始化錯誤只允許一次乾淨Worker回退，轉回同一份ImageBitmap，原三十秒偵測預算不重新起算。舊Worker先解除監聽並終止，不讓半初始化Emscripten全域或晚到錯誤干擾新工作；兩次都失敗、取消與製片失敗仍由原成功交換點保全舊路徑／舊成品。

兩套JS／WASM均在共用白名單，WASM各固定SHA，模型原SHA不變；SW與封裝仍核對完整性。包多帶約14MB SIMD，換取同一份離線包可在不同能力環境使用。沒有改模型、門檻、補邊、平滑、取樣或匯出，也不採UA猜測、雲端推論、同Worker污染後重試或以少取樣換速度。
