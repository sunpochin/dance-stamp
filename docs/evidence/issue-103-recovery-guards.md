# #103：清單、離線與草稿的恢復保護

## 怎麼用、為什麼有效

影片清單像放影片的抽屜。清單一時讀不到，不代表裡面的影片消失了：先保留原本畫面，打開「影片副本與重新連結」，再按「重新檢查清單」。這只重新查看抽屜，不會清空筆記或影片。

打開「離線、容量與更新」，按「重新檢查離線與容量」。如果檢查等不到回覆，畫面會說暫時無法確認；先保持連線，稍後再按一次。這像問人「準備好了嗎」卻沒聽到回答，不能擅自當成已準備好，也不需要把原有東西丟掉。

清單裡的「另存影片檔」也能保留看不懂格式的原始檔。格式不明時會下載成 `.bin`，完整保留原始內容；這是交還原檔，不代表它已修好或能播放。想像箱子標籤看不懂，仍把整箱交還給你，保留日後修復的機會。

例如你正在替 Salsa 的一個八拍寫「右腳先走」，還沒按儲存就想重新整理。標記、拍點或動作還沒存完時，重新整理會由瀏覽器提醒。選擇留在頁面，剛才打的字仍在；可再保存，或用產品的取消按鈕明確捨棄草稿。原因是資料仍放在原本的頁面裡，程式不會偷偷幫你存下或丟掉。

| 案例 | 故障／動作與使用者結果 |
| --- | --- |
| `recovery-offline-timeout` | 明示截住一次 CHECK_OFFLINE 請求，等產品原本五秒期限顯示未知；資料及 cache keys 不變。解除後由公開按鈕送給真正 worker 再檢查成功。沒有縮短計時器或派送假回覆。 |
| `recovery-inventory-read` | 只中止原生 media.getAllKeys 的 readonly 交易；引擎送 trusted AbortError／abort。開課程引發的清單讀取失敗顯示保留資料說明，再按重新檢查，三份原媒體及清單恢復。沒有把讀失敗當成空庫。 |
| `recovery-unknown-media` | 明示在隔離原生庫替換一份已存自拍為已知未知格式 bytes，metadata及其他兩份媒體不變；重載清掉 session File，再從真正清單下載 `.bin`，逐 byte 指紋等於未知原檔。撤除 QA 故障、恢復精確原 bytes 後，同 asset／take 經公開入口重開，舊 VS 仍可取回。不是自然資料損壞重現或影片修復。 |

每條恢復後真正下載舊 VS，從磁碟比對完整 bytes／SHA-256，再正常重載比對全部 metadata／媒體。擷取相機／麥克風／螢幕的入口在此四案封鎖，呼叫必須0；沒有接觸日常瀏覽器或真人素材。
