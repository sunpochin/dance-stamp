# 簡化雙片介面的 Safari 局部結果

先選老師與自己的合成測片，將同一動作設在 12／4 秒，再預覽、輸出、真正下載並從本機檔案播放。這輪已完成 14 份；第七次一分鐘重複因頁面切到背景而停止，舊成片仍保留。**沒有完成十輪連續、六個剩餘配置、真機或完整 G1–G7 驗收，#11 保持開啟。**

## 固定來源與操作

- 產品啟動來源 `30aafa9039432eabc784ed546d647109bff5a4dd`，靜態 `b9d490d8c16b71f7`；macOS 27.0.1（26A434）、一般原生 Safari 27.0.1（22625.1.29.11.28），Python 3.15.2／FFmpeg 8.1.2／Bun 1.4.4。不是後續 main 的驗收。
- 原生選檔、確認、輸入、播放、停止、輸出及 Save As 都由實際介面操作；未替換播放、seek、影格回呼、解碼器或錄製器。預覽後已按停止，才開始匯出矩陣。
- 來源為既有公開產生器的 320×180 合成 MP4：示範 80 秒、660Hz；練習三速度各 75 秒、880Hz；兩側含 12-bit 影格碼。示範起點 12 秒、練習起點 4 秒。原片 session-only，不自動保存副本。
- 僅注入禁止硬體擷取與被動觀察；HTTP 政策亦拒絕相機／麥克風。34 份完整快照均無硬體呼叫或未確認儲存。100ms 樣本記錄前景、焦點、來源時間、AudioContext；各成功匯出樣本來源不在 viewport。沒有把顯示來源視窗當作本輪前提。
- 啟動時九份產品 JS SHA 與 Git 物件逐一核對；一直使用同一已載入頁面，未重新載入。結尾發現其他作業已更新工作目錄至 `6bea8875d6a1858c17b7d3fa53f1403e02c67f9f`、dist 至 `894178ee5c77a5a8`，因此停止矩陣、不再重載或把結果移記新版；沒有覆蓋其他工作。
- 注入 HTML 與原始 HTML 不同，SW 未修改；本輪不提供離線驗收。

## 檢查工具的可重現問題與修正

原公開 `analyze-comparison.py`（SHA `ebeee4b1cf5318f5ab650b7ef22ee17096a56dad3eb740741f125b933a083299`）對第一份已完整解碼／原生重播的 WebM 回 `KeyError: 'duration'`；原碼及 stdout／stderr 保留在上述副本。這是量尺失敗，不能算產品失敗。

修正從同步 main `69ebdd589112cd9ee85881778a98c4917c01bb74` 獨立分支進行，只改分析器與自查／文件／CI，不改產品、錄製器或品質門檻。沿本輪測試前已凍結的分析方法補 WebM PTS／PCM 片長與兩側覆蓋，另對齊現行自然變調的頻率及既有峰值／聲源護欄；[設計與排除方案](../../TECHNICAL.md#雙片檔案量尺的-webm-片長與自然音高)。

新增 11 組真正編碼的量尺控制：缺片長 WebM、MP4、0.75×、0.5×、無聲、雙鏡像六個正例；自己超前一秒、錯 880Hz 聲源、慢速仍是舊 660Hz、截短與兩側共同重播五個負例，均在預期護欄接受／拒絕。修正版另重算上述 14 份原始下載，共有的 17 個結果欄位與測試前凍結分析逐項相同；新音高下限與非預期頻率檢查亦通過。沒有重跑產品或覆寫原分析。

本機原 `bun run check` 通過：657 tests／0 fail／3,316 expects，333 檔公開掃描、型別、原 lint（19 項 info）與建置均通過；完整 diff 已人工檢查。11 組量尺控制加入既有 CI 的 FFmpeg 工作，不為此新增產品相依或改動瀏覽器案例範圍。CI 結果另綁 PR head，不以本機結果代簽。

本輪只證明合成雙片的局部像素同步、聲源／音高與成檔保全。連續音沒有閃光／提示音配對，不能代表絕對聲畫時間差；320×180 來源合成 1280×720 不能證明真實相機細節品質。實體裝置、喇叭／藍牙、熱／電池／記憶體峰值、真實重開／重連及完整 G1–G7 仍未驗證；沒有合併或發布授權。
