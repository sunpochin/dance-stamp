# #103：恢復過程再失敗的資料保全

## 怎麼用、為什麼有效

錄影突然提早停止時，先用「未完成原片」下載已錄到的內容。即使連「這段錄影已中斷」都存不進去，原片碎片仍留在本機；重新開啟同一頁，再從該段的「開啟自拍／恢復」取回。取回的短片仍標為中斷，請先看完並保存，不能當作已錄好完整十五秒。這像先把散落的紙收好，標籤沒貼成功，也不會把紙一起丟掉。

重新連結影片時，若選了空檔，連原本候選的預覽也恢復失敗，先按取消，再選正確的原片、實播預覽並勾選確認。兩次失敗都不會把候選直接當成已保存的原片；原筆記、時間與已存 VS 保留。取消像先把打不開的盒子放回桌上，再重新拿正確的盒子，不必清空整個抽屜。

## 兩條追加驗證

- `capture`：保留原全部步驟／斷言，在末尾真正成檔舊 VS、保存非空筆記，再開原生合成相機。已有原生 chunks 落盤後，真正停止原生編碼器製造明示早停，只對新段的 interrupted 狀態更新呼叫原生交易 abort。核對 trusted AbortError／abort、原始未完成提示、相機 tracks 全結束、完整已確認 metadata／revision 不變、全部舊媒體與其他 chunks 指紋相等。真正下載未完成原片後，同 profile 重載並走該 take 的公開恢復，原片 bytes 完整相等、仍標 interrupted、只清自身 chunks；再下載恢復原片與舊 VS，最後重開逐表核對。
- `relink`：保留原同名短片與超界筆記斷言，再建立真正舊 VS 和有兩份保存媒體的缺片基準。公開選片預覽成功後，先用真正 reload／原生提醒選擇留下，確認同頁候選及完整資料仍在，再選空檔；只在舊候選重新建立解碼 URL 時明示替換成無效 bytes。真正引擎送 trusted error，原空檔錯誤仍保留，完整 metadata／revision 及所有媒體指紋不變。公開取消清除預覽，再選同一正確原片、實播勾選確認；只增加一次 revision，沒有偷偷保存 session 原片，真正舊 VS 下載指紋相等，重開後缺片狀態與原資料保留。

兩種注入皆只在隔離合成資料啟用一次，不偽造事件或完成收據，不呼叫產品內部 handler，不移除未知保存、原完整性與重新連結護欄。原生相機只使用既有假裝置旗標，明確要求 audio=false；不開硬體麥克風、不接觸真人影片。早停原片是實際編碼 bytes；第二次解碼失敗是明示替換測試輸入，不冒稱自然平台故障。
