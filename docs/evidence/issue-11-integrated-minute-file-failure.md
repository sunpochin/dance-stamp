# #11 整合候選原生 Safari：六份品質通過，一分鐘聲畫差失敗

日期：2026-11-01。#11 與完整 G1–G7 保持未完成。

## 小朋友也能懂的讀法

拿兩支會顯示時間碼、發出提示音的合成影片做比較，像用拍手檢查畫面與聲音有沒有對上。15秒與30秒的三種速度都在原標準內；第一支一分鐘影片有一次聲音先到，超過原標準，所以停下來保留它，繼續找原因。

讀這份紀錄時，先核對受測版本和檔案指紋，再分別看「品質」與「播放」。下載後離開網站，直接打開原檔確認能播完；另外用成片裡的畫面時間碼與聲音量時間差。這樣才能分清楚「檔案可讀」與「動作、聲音有對上」，也保留失敗檔供後續判斷。

- 原生媒體來源：乾淨 `81d875634a7248fe0e4441f0072176fbfef2e056`，PR #178 的整合候選；靜態版本 `e38ad0016d1001da`。

- macOS 27.0.1／原生普通Safari 27.0.1（22625.1.29.11.28）；Bun 1.4.4／FFmpeg 8.1.2。

- 真正原生選檔、設定與匯出；每份以Safari原生Save As實際下載，完整bytes／SHA皆等於新增ready VS的完整IndexedDB Blob。沒有拿旁聽副本冒充原生下載。
- 原產品、原測試及門檻不改。沿已凍結的比較分析器（SHA `bfc00a8e9a0ab3a654d7903e68725cf8d17db643fa3420b6213e09eeea76a4e6`）及提示音分析器（SHA `5399df7f10f9f2c8876a64a9953523fbc66a3f89b22a2bd9284cb9851fcd09ba`），沿v5 RMS 0.03、`0.25/rate`分組、半開區間及100ms聲畫界線；[正式門檻](../RECORD_COMPARE.md)不放寬。

## 保存、重開與關站後播放

基準22份舊媒體及其完整資料列逐次保留；新增七份VS後為29份／70,379,855 bytes、revision182。停止後兩次、同origin原生重開後再兩次的完整library（含revision）與所有媒體id／MIME／大小／SHA／bytes均精確相同，沒有reset、重新匯入或重連。沒有儲存未確認、讀回錯誤、未處理例外或硬體擷取呼叫。這是同profile重開，並非新程序、離線或跨裝置驗收。

關掉自有產品頁與主機、實測原網址拒絕連線後，七份**原生下載原檔**分別在新Safari file視窗開啟，皆自然到Play／Elapsed＝Duration／位置1。沒有Agent播放、音量、seek或恢復操作；中途29秒仍顯示Pause的一份僅等待同一檔案自然結束，沒有重開或拖動。初次AX皆仍在讀取metadata，只有部分檔案另有途中Pause觀察，因此不宣稱逐份觀察到0秒、原生播放器error／dropped數字或人工聽感通過。案例07的聲畫品質失敗不改標。

七個自有file視窗已各自關閉，原日常Safari視窗保留；沒有宣稱關閉全部網站視窗。自有產品主機與檔案播放持鎖程序均退出0，兩個原埠在播放後皆實測拒連，各自核對nonce釋放自有鎖。

### 保留的操作中斷

首次選示範片返回時，頁面原生短暫hidden29ms，產品停止載入；當時沒有任何匯出，完整舊資料不變。一次有界對照改用原生選檔器Return成功載入，此後選片沿此方式。沒有把這次操作中斷當成已修復的產品問題。

第三份已成檔後，原生下載工具曾逾時，並兩次回報Safari有其他操作；原因未判定。保存當時畫面與收據後，從同一現成Blob完成Save As，實際951,418-byte下載等於原先完整讀回，沒有重做匯出或重用另一份結果。早期只完成IDB分析的局部紀錄仍保留，與後來的真正下載分開。
